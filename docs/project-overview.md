# Project Overview — Robotic-Arm Imitation Learning with LeRobot

This project uses the LeRobot framework and a 6-DoF SO-ARM101 robot arm to run an end-to-end imitation-learning experiment — from data collection through model training to real-world deployment. The goal: have the arm complete pick-and-place tasks from camera input, and test how well a behavior-cloning model generalizes in the real world.

For data collection, I used a pair of SO-ARM101 arms for teleoperation: the operator drives the Leader arm to control the Follower, while the system records RGB camera frames, arm joint states, and action sequences. After cleaning and format conversion, this yielded 49 valid demonstrations — about 12,625 frames at 640×480 resolution and 30 FPS. I then trained an ACT (Action Chunking Transformer) model on an AutoDL cloud server with an RTX 4090. The model takes RGB images and six-dimensional joint states as input and predicts continuous action chunks; training ran 50,000 steps on roughly 51.66M parameters. After training, I moved the model to a local RTX 3060 Ti machine, connected a camera and the Follower arm, and ran inference tests. Along the way I solved engineering problems spanning camera-backend compatibility, LeRobot v2.1→v3.0 dataset conversion, HuggingFace access in offline environments, training dependencies, model version incompatibility, and local deployment.

Training converged smoothly — loss fell from 6.793 to 0.110, about 98.4% — and the model loaded locally and produced valid arm actions. In real tests, however, the arm did not generalize: placed at different positions, it kept reaching toward the grasp position most frequent in the training data, often repeating the same motion. The root causes: insufficient diversity in the training data (a single object type, limited variation of initial positions and target containers, no language annotations), plus a visual distribution shift between the overhead Astra camera used in training and the side-view webcam used at inference. The model's large parameter count relative to the small dataset also made it easier to memorize fixed patterns than to learn a genuinely vision-dependent grasping policy.

The deepest lesson of this project: **a low loss does not mean the robot has learned the task.** A behavior-cloning model can fit the training data beautifully while merely replaying the most common action patterns. Once the robot makes a small error during execution and enters a state never covered by the demonstrations, errors compound — the distribution-shift problem fundamental to imitation learning. In the next stage I plan to collect richer data — more objects, more initial and target positions, and the same camera at train and test time — and to add data augmentation and DAgger-style closed-loop collection, where the expert supplies corrective actions for the off-track states the policy actually encounters. Going further, I will attach a language instruction to every demonstration and move toward vision-language-action models, so the arm does not just imitate motions but understands task intent — *which* object to pick up, and *where* to place it.
